# recab findings

> Superseded scope, 2026-11-10: this is a historical refactoring snapshot, not the current recab product plan. Recab owns system updates and symmetric A/B continuation, including equivalent initial systems and incremental preparation that preserves pending changes through updates. Follow [the current requirements](../../tools/recab/REQUIREMENTS.md); retain the old findings below as historical evidence only.

One shared queue, most severe first within each group. Each finding says what
its evidence is: **observed** (read in the code or in command output),
**contract** (code and README/REQUIREMENTS disagree) or **inferred** (follows
from the code; nothing was run). "Raised by": P = primary (Claude); A, B, C =
the independent challengers ([slices.md](slices.md)). Every challenger finding adopted here was re-read by the primary;
line numbers are those at `d4365a9e`. (An earlier version of this file said
challenger B's line numbers were offset; they were right, and the primary's
numbers for `stage.rs` and `store.rs` were wrong. Corrected 2026-11-08.) Severity describes what a machine or operator suffers.
All findings are open. Tasks are in [tasks.md](tasks.md).

## Checked and found sound

- The run lock covers every mutating command and is taken before the reads it
  plans from; `trial` waits for startup before locking (A).
- `apply`'s default-change order (clear one-shot, strip options, loader.conf,
  variable, restore loader.conf on failure) and its classification (A).
- State schema handling: never lowered, unknown top-level fields kept (A; nested
  case is F-M6).
- The committed JSON schemas match the Rust types field for field;
  `cargo xtask gen --check` reports them current (C, P).
- No dead code in `init.rs`, `stage.rs`, `carried.rs` (B).
