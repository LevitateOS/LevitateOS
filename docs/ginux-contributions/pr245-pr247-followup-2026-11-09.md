## #245: caller-independent clone arguments

The previous `fe363cf2` implementation wrote the cleared cgroup flag into
caller memory. The new readonly-input regression fails on that binary
(`readonly-clone=0`). The corrected implementation copies the input once,
validates the 64-byte minimum, page-size maximum and zero extension tail,
checks ownership of the virtual cgroup descriptor, and changes only its
private snapshot. It then executes the original host clone3, preserving
CLONE_CLEAR_SIGHAND, declared pidfd output, VM/VFORK and explicit child stack
semantics. It restores caller argument registers and result after removing
the private mapping in both parent and child. No substitution with the
less expressive legacy clone syscall is used.

Ginux does not rewrite the input structure. Ordinary kernel-declared output
pointers still apply, including intentional aliases to caller memory.
Readonly caller input succeeds when its declared outputs are independently
writable. Kernel errors, unreadable input, invalid sizes/tails and allocation
collisions preserve input bytes.

The native owner reserves `[0x600000000000,0x600000080000)` for transient
readonly snapshots: one 4 KiB page per active task slot, within existing
memory and task limits. Workload mmap/mprotect/munmap/madvise/mremap requests
cannot mutate that range; denial audit identifies `clone-arguments`. A
pre-existing mapping is never replaced. Capture requires process_vm_readv
and fails closed if the host cannot provide it. SIGCHLD delivery is deferred
until the private protocol completes. Death during that protocol enters the
existing fail-closed instance teardown, preventing a stale shared-VM mapping
from being retained by a surviving instance. This abort rule is source-backed;
the runtime controls below establish normal, kernel-error and allocation-error
cleanup, not every adversarial death schedule.

The virtual cgroup adaptation still starts the child in its parent's host
cgroup. This task adds neither real host cgroup placement nor resource
enforcement through virtual membership.

Retained and added runtime controls pass:

- Original virtual-cgroup child/status test and invalid/ordinary-FD denials.
- Readonly input; parent and child input preservation; kernel EINVAL; size,
  unreadable-pointer and extension-tail cases; version-0 and zero-tail success.
- Actual signal-handler reset, pidfd output, VM/VFORK and child-stack behavior.
- All five reserved-range denial controls with the correct audit owner.
- 160 repeated snapshot calls and real parent/child map removal.
- Deterministic mutation after capture on the production binary: an outer
  ptracer stops only Ginux at its real SETREGS entry, changes the original
  fixture's flags, verifies that writing the private snapshot fails with
  EFAULT, then lets the captured call finish. Both cleanup mappings are absent;
  the child exits with the captured behavior and caller mutation remains.
- A separate ELF fixture already maps the reserved page: clone3 returns
  EEXIST and both its sentinel mapping and input structure remain intact.

The snapshot runner is part of the existing `make test-native-supervision`
target; no production test hook or disabled check was added.

## #247: host lifetime owns reap accounting

The previous `4c09332e` binary fails the new null-siginfo regression with
`native virtual child failed`. Host children had been reaped while their
virtual slots remained allocated. The corrected supervisor pins each waitable
child before it runs and uses that exact pidfd's final-reap POLLHUP state to
reconcile the process table. It does not infer reaping from caller siginfo, a
numeric PID's continued existence, or the call's success errno. PID reuse
cannot substitute another task for the pinned object.

The actual host waitid call remains unchanged, retaining selector, option,
rusage, blocking, WNOHANG, WNOWAIT and errno behavior. Even a reap followed by
a rusage copy-out EFAULT closes the pin and releases the virtual slot. An
exited zombie or stopped/continued notification does not count as final
reaping. Pins close on wait4 reclamation as well. Private pins do not change
the public FD budget; unavailable required pins fail the instance closed.
Non-leader threads that older pidfd interfaces cannot open remain in their
existing non-waitid-reapable lane. General native thread/job-control
limitations are not expanded into conformance claims.

The same inspection found and corrected RSI restoration: P_PID translation
now returns the original selector register, including high bits, on successful
waits, errors/restarts and contract denial. Denied calls never borrow stale
selector state.

The existing non-null WNOWAIT/200-reap test remains. New controls pass for
null WNOHANG, null WNOWAIT followed by reap, rewait ECHILD, invalid options,
rusage copy-out failure, selector preservation and explicit denial. Another
800 waits alternate P_PID, P_ALL and P_PIDFD with valid rusage under
RLIMIT_NOFILE512. This exercises both table reuse and private-pin reclamation
without widening public limits. Host pidfd final-reap readiness, as in Linux
6.12, is a declared requirement.
